# miniChemistry Quick Project Documentation

This document gives a **high-level map** of the repository and the common usage patterns, without detailing every class/function.

## 1) What this project is

`miniChemistry` is a Python package for:
- modeling substances and basic reaction entities,
- predicting and balancing reactions,
- doing stoichiometric/quantity calculations over reactions,
- generating and solving chemistry-style exercises.

The package exposes a CLI entrypoint (`reaction`) and Python APIs.

---

## 2) Repository structure (high level)

### Root
- `pyproject.toml` — packaging metadata, dependencies (`chemparse`, `sympy`), and CLI script registration.
- `README.md` — project description and conceptual feature overview.
- `UPDATES.md` — changelog-style updates.

### `miniChemistry/Core`
**Domain model + chemistry logic**
- `Substances/` — representations for particles, ions, molecules, and conversion helpers.
- `Reactions/` — reaction abstractions and concrete reaction types (`MolecularReaction`, `IonGroupReaction`, etc.).
- `Tools/` — parser/equalizer/sorting and reaction prediction tooling.
- `ReactionMechanisms/` — mechanism and restriction logic used by reaction prediction.
- `Database/` — chemical data tables/files (periodic table, solubility, half-reactions, activity series).
- `CoreExceptions/` — domain-specific exceptions.

### `miniChemistry/Computations`
**Calculation layer over reaction/domain objects**
- `ReactionCalculator.py` — core stoichiometric workflow engine.
- `SSDatum.py` — data container for “substance + symbol + value + unit”.
- `Problems/` — parsing and solving text-defined problems (`ProblemParser`, `ProblemSolver`, strategy-specific problem handlers).
- `CalculatorFiles/` — formulas/units/assumptions used by the computational layer.
- `ComputationExceptions/` — computation-specific exception types.

### `miniChemistry/EXAMPLES`
Runnable examples for:
- direct API usage,
- balancing reactions,
- limiting reagent/excess flows,
- exercise generation.

### `miniChemistry/Utilities`
Shared helper utilities (checks, file helper, exceptions).

## 3) Typical usage patterns

## Pattern A — Parse and balance reaction quickly
Use the reaction model from a string and read `.equation`:
- via API: create `MolecularReaction.from_string("...")`
- via CLI: run `reaction "..."`

Useful for “give me balanced equation” workflows.

## Pattern B — Stoichiometric solving over a reaction
Common flow:
1. Build/parse reaction (`MolecularReaction(...)` or `.from_string(...)`).
2. Create `ReactionCalculator(reaction)`.
3. Write known data as `SSDatum` entries (e.g., mass of reagent/product).
4. Compute/derive moles (`compute_moles_of`, `derive_moles_of`).
5. Compute requested targets (`compute(...)`).

This is the primary programmatic workflow for chemistry calculations.

## Pattern C — Solve exercises from compact text
`ProblemSolver` accepts structured text blocks and chooses solution strategy:
- if reaction + multiple reagent data → limiting reagent logic,
- if reaction + one effective basis datum → direct stoichiometric scaling,
- if no reaction → quantity-calculator-only mode.

This is useful for batch generation and auto-solving of school-style tasks.

## Pattern D — Reaction prediction pipeline
Prediction is orchestrated through `Core/Tools/ReactionPredictionTool`:
- classify reagent signatures,
- select mechanism + restriction from CSV mapping,
- generate products and validate restrictions.

This separates “what kind of reaction is this” from “how to compute products”.

---

## 4) Data and configuration patterns

- Chemical reference data lives under `Core/Database` (mix of Python modules + CSV/XLSX/plain files).
- Computation formulas/units are loaded from `Computations/CalculatorFiles` at import/runtime.
- Example-generation scripts define configurable constants near script bottoms for exercise output tuning.

---

## 5) How to navigate the codebase quickly

If you are new to this repository, this order is efficient:
1. `README.md` (conceptual overview)
2. `pyproject.toml` (packaging + entrypoints)
3. `miniChemistry/Core/Reactions/__init__.py` (main reaction classes)
4. `miniChemistry/Computations/ReactionCalculator.py` (calculation core)
5. `miniChemistry/Computations/Problems/ProblemSolver.py` (text problem orchestration)
6. `miniChemistry/EXAMPLES/_Code/*.py` and `miniChemistry/EXAMPLES/Create_exercises.py` (real usage patterns)

---

## 6) Practical “when to use what”

- **Need only balanced equations** → `MolecularReaction.from_string(...)` or CLI `reaction`.
- **Need quantitative answer for one reaction scenario** → `ReactionCalculator` + `SSDatum`.
- **Need many autogenerated/parsed tasks** → `ProblemSolver` with data-string templates.
- **Need predicted products for reagent combinations** → `ReactionPredictionTool` path.

---

## 7) Notes for contributors

- The code is organized by **domain (Core)** vs **computation strategy (Computations)**.
- Examples are the best source of intended usage style.
- Exception types are split by subsystem (core vs computation), which helps debugging large scripted runs.
